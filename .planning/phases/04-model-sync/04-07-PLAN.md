<objective>
The two escape hatches, and the reason they are two.

`Hubspot::withoutSyncing()` is in-process and stops a dispatch; `HUBSPOT_DISABLED` is environment-level
and survives any process boundary, including a queue worker that started before the switch was
flipped. Without the first, `migrate:fresh --seed` fires thousands of API calls. Without the second,
nothing protects a worker that is already running.

Purpose: ROADMAP SC5's last clause, and the config-cache hazard `04-RESEARCH.md` verified in framework
source — a closure in `config/hubspot.php` throws under `php artisan config:cache`, which is a
production-breaking regression rather than a test-suite inconvenience.
Output: one gate consulted at both dispatch and handle, and a suppression API that is exception-safe
and nestable.
</objective>

**`HubspotManager`** gains the suppression state, beside the fake state it already owns:

- `withoutSyncing(Closure $callback): mixed` — saves the previous suppression state, sets it, runs the
  callback, restores the SAVED value in a `finally`, and returns the callback's value. Restoring the
  saved value rather than clearing the flag is what makes nesting correct; clearing it un-suppresses at
  the inner call's exit while the outer call is still running.
- `syncingSuppressed(): bool`
- `isFaked(): bool` — public, because `SyncGate` needs it and `fakeOrFail()` is private and throws.

**`Sync\SyncGate`** is a `final` class with one question: may a sync proceed right now? It answers
false when `config('hubspot.disabled')` is true, false when `HubspotManager::syncingSuppressed()` is
true, and false when the application environment is `testing` and no fake is bound. Each operand is
separately observable, because the MSI floor measures exactly that.

The testing-environment default is **runtime logic and never a config value**. `config/hubspot.php`'s
`disabled` key keeps its plain-bool-from-`env()` shape. A closure default there works under `artisan
serve` and throws under `php artisan config:cache`, because that command serialises with
`var_export()` and rethrows a `LogicException` naming the non-serialisable value — a production-
breaking regression in any consumer that caches config, which is a very common production step. Say
this in `SyncGate`'s docblock so nobody moves the logic back into the config file.

Bind `SyncGate` in `ServiceProvider::register()`. It must NOT be a shared singleton constructed before
a test's `Hubspot::fake()` call, for the reason the gateway bindings are non-shared: a gate that
captured the manager or the config at construction would answer from stale state after a container
swap.

**Consult it in two places.** `HubspotObserver` asks before every dispatch, composed with 04-05's
event gate rather than replacing it — suppression must stop the dispatch, or a seeder leaves a queue
backlog that fires the moment the worker drains. `SyncHubspotObjectJob` and `ArchiveHubspotObjectJob`
ask again in `handle()`, because `withoutSyncing()` is in-process only while the kill switch is
env-level and survives a process boundary; a job queued before the switch was flipped must not fire.
Document that asymmetry in both places: it is the whole reason there are two hatches rather than one.

**Expect fallout and fix it here.** The testing-environment default did not exist while 04-02 through
04-06 were written. Run the full suite and check every Sync test: any that dispatches without binding
a fake now becomes a silent no-op. Install a fake in those tests rather than weakening the gate — a
test made green by loosening the kill switch is worse than the failure it hides. List every test you
touched in the summary.

`HUBSPOT_DISABLED` also kills inbound webhook handling per SYNC-05's wording; no webhook path exists
until Phase 5, so nothing is implemented for it here. State that in the config comment rather than
implying the key is sync-only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seeder / import / backfill → HubSpot | Bulk local writes that must not become bulk CRM writes |
| process boundary (dispatcher → worker) | In-process suppression does not cross it; an env var does |
| `config:cache` → production runtime | A non-serialisable config value fails the cache step and takes the deploy with it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-28 | Denial of Service | `migrate:fresh --seed` firing real API calls | high | mitigate | `withoutSyncing()` stops the DISPATCH, asserted with `Bus::fake()` as well as a request count, so no backlog remains to fire when the worker drains |
| T-04-29 | Tampering | suppression not surviving a process boundary | high | mitigate | `HUBSPOT_DISABLED` is env-level and re-checked in `handle()`; the asymmetry with `withoutSyncing()` is documented in both places |
| T-04-30 | Denial of Service | `config:cache` throwing on a closure default | high | mitigate | The testing-environment default is runtime logic in `SyncGate`, never a value in the config array; asserted by a `var_export()` criterion. `ConfigCacheCommand` rethrows a `LogicException` naming the non-serialisable value |
| T-04-31 | Tampering | suppression leaking past a thrown callback | medium | mitigate | The previous state is restored in a `finally`, and the saved value is restored rather than the flag cleared, so nesting is correct too |
| T-04-32 | Repudiation | a test made green by loosening the kill switch | medium | mitigate | Earlier Sync tests broken by the testing default are fixed by binding a fake, never by weakening the gate; every touched test is listed in the summary |
</threat_model>
