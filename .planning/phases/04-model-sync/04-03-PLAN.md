<feature>
  <name>`$hubspotMap` / `$hubspotUpdateMap` resolution</name>
  <files>src/Sync/PropertyMapper.php, src/Sync/SyncHubspotObjectJob.php, tests/Unit/Sync/PropertyMapperTest.php, tests/Feature/Sync/UpdateSyncTest.php</files>
  <behavior>
    - A literal attribute name resolves that attribute's value.
    - A dot-notation path resolves across a relation.
    - A closure receives the model and its return value is used verbatim.
    - A dot-notation path across a NULL relation omits the key from the bag rather than throwing or sending null.
    - A closure returning null omits the key, on the same rule.
    - An empty string is NOT null and is sent verbatim — that is how a value is deliberately blanked.
    - An empty map produces an empty bag and no request is attempted.
    - `$hubspotUpdateMap`, when the model declares one, replaces `$hubspotMap` on the update path; when it does not, the update path uses `$hubspotMap` unchanged.
    - A model with an existing `hubspot_object_links` row is updated by its stored HubSpot id; a model without one is upserted on the binding's `id_property`.
  </behavior>
  <implementation>See the tasks below. `PropertyMapper` takes and returns primitives plus the model; it performs no I/O and holds no state.</implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer-authored `$hubspotMap` closure → package | Arbitrary first-party code runs inside the job on the worker |
| resolved property bag → HubSpot record | The bag decides what a CRM record's fields become |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-11 | Tampering | null resolved value reaching HubSpot | high | mitigate | Null omits the key. A null relation traversal and a deliberate clear are indistinguishable at this layer, and a silent property clear on a live CRM record is unrecoverable through this package; an empty string is the explicit form and is sent verbatim |
| T-04-12 | Tampering | update addressed by a re-derived id property | high | mitigate | The update leg addresses the stored HubSpot id from `hubspot_object_links`. Re-deriving the address from a mapped property would repoint the write at a different record the moment that property changed — this package's silent-wrong-id threat class |
| T-04-13 | Input Validation (V5) | `$hubspotMap` closure execution | low | accept | The closure is first-party consumer code in the consumer's own model class; the package neither sandboxes nor validates it. Recorded because ASVS V5 applies to the surface, not because untrusted input reaches it |
| T-04-14 | Information Disclosure | mapped values in a queue payload | medium | mitigate | D-09: the map resolves on the worker against the re-fetched model, so no resolved property value is ever written to the queue store |
</threat_model>
