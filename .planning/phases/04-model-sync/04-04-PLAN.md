<objective>
Complete SYNC-01a's binding surface and REG-01b's resolution path.

04-02's tracer proved one model, one binding, one link row. SC2 asks for three models bound to
`contacts` at once and for an API-only object type usable with no local model at all; D-06 asks for a
relation and three query scopes rather than a column; REG-01b resolves through that relation. This
plan delivers all of it, and writes down what SYNC-01b is not.

Purpose: SC2 is the criterion tapp's global `contact_id_column` cannot express, and it is the
originating application's actual shape — `Lead`, `Contact` and `HealthCheckIntake` all syncing to
contacts.
Output: the trait's full public read surface, a multi-binding feature test, and a directed error for
a model that applies the trait without declaring a binding.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model class → link row | The class name is half the key that keeps three contact-bound models apart |
| consumer `hubspot.models` → object type | A missing entry decides whether a model writes anywhere at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-15 | Tampering | link resolution across three models on one object type | critical | mitigate | The MorphOne is discriminated by `model_type` and the unique index carries it; the feature test asserts three distinct rows and three distinct ids, so a shared-row regression fails rather than merging two people's CRM records |
| T-04-16 | Tampering | a trait-using model absent from `hubspot.models` | high | mitigate | `ConfigurationException::unboundSyncModel()` — throw naming the fix, never a guessed object type. Guessing would write a local row into whichever CRM object type happened to be first |
| T-04-17 | Information Disclosure | `whereHubspotId()` matching across model classes | medium | mitigate | The scope constrains the morph relation to the querying model's own class; a cross-class match would let one model's query surface another model's linked record |
| T-04-18 | Denial of Service | `pendingHubspotSync()` missing its stale leg | low | mitigate | Both legs asserted in task 1; a scope missing the stale leg silently under-reports after every restore, which is a backlog that never drains rather than an error |
</threat_model>
