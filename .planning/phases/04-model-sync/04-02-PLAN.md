## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer config (`hubspot.models`) → package behaviour | An operator-authored map decides which CRM record a local row writes to |
| Eloquent event → queue payload | Model state crosses a process boundary and is re-fetched on a worker |
| queue worker → HubSpot CRM | The only outbound network write in this phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | `ModelBindings` `id_property` | critical | mitigate | D-12: a binding without `id_property` throws at boot naming the fix. A misconfigured id property silently upserts on the wrong field and merges two unrelated HubSpot records — this package's recurring silent-wrong-id threat class (T-02-04/T-02-08 precedent) |
| T-04-06 | Tampering | `HubspotObserver` binding lookup | high | mitigate | The binding is resolved by `get_class($model)` at call time. `Model::observe()` discards an instance, so constructor-captured binding data would make the second bound model sync as the first one's object type — silently, and only once a second model is bound |
| T-04-07 | Information Disclosure | `SyncHubspotObjectJob` payload | medium | mitigate | `SerializesModels` stores an identifier, not attributes, and D-09 resolves the map on the worker so no mapped property value is ever written to the queue store |
