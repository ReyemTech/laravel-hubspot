<objective>
Turn the tracer's single `created` path into the auto-sync event surface SYNC-03 specifies, and prove
the request-lifecycle contract.

One trait, one observer, one queued job, with the object type carried as data. The events that fire
are `auto_sync.on`'s, narrowed per model by `$hubspotAutoSync`, killed outright by
`auto_sync.enabled = false`. Nothing goes in the consumer's `AppServiceProvider`. And the assertion
STANDARDS §11 has committed to in the present tense since Phase 1 — no API call in a request
lifecycle — becomes a test rather than a claim.

Purpose: SC1 and the first half of SC4.
Output: a gated generic observer, the `auto_sync` config block, and the D-17 restore guard placed
where `updated` is born rather than bolted on a plan later.
</objective>

opt-in and why (04-06 adds the delete keys — do not add them here), and `queue` defaulting true.

which would be a production-breaking regression in any consumer that caches config, not merely a test
failure.

Add `updated` to `Sync\HubspotObserver` beside `created`, and factor the gate into one private method
both call. The gate resolves, in order: the per-model `$hubspotAutoSync` property when the model
declares one — an array narrows to exactly its listed events, `false` disables the model outright —
otherwise `config('hubspot.auto_sync.on')`; and independently `config('hubspot.auto_sync.enabled')`.
Write it so each operand is separately observable, because that is what the three matrix tests assert
and what the MSI floor measures. Read the per-model property through a method on the trait rather than
by touching the property directly from the observer, so a model that does not declare it has one
defined answer instead of a property-existence check at each call site.

captured in the observer's constructor: `Model::observe()` registers a class name and re-resolves from
the container on every fire, so captured state is silently discarded and the second bound model would
sync as the first one's object type.

non-null. Docblock it with the verified reason — `SoftDeletes::restore()` calls `save()` internally so

restore. State that `getOriginal()` is the only signal stock Eloquent exposes for this, and that a
model without a `deleted_at` attribute at all reads as null and is therefore unaffected.

Update `ServiceProvider::boot()` only if the attachment loop needs the new events registered; the
class-string `observe()` call registers every method the observer defines, so it probably needs no
change — confirm rather than assume.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Eloquent event → dispatch decision | The gate decides whether a local write reaches a live CRM |
| request lifecycle → HubSpot | A synchronous call here would put HubSpot's availability on the consumer's request path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-19 | Denial of Service | a synchronous API call in a request lifecycle | high | mitigate | The zero-HTTP contract is asserted with `Bus::fake()` and `assertRequestCount(0)` in one test; asserting only that a job was pushed would pass against an implementation that also called the API |
| T-04-20 | Tampering | the per-event gate | high | mitigate | Three independent-operand tests; a gate whose operands cannot each flip the outcome alone is a gate that has silently stopped gating, and `pest --mutate`'s floor is what keeps it honest |
| T-04-21 | Denial of Service | a restore costing two API calls | medium | mitigate | D-17's `getOriginal('deleted_at')` guard, placed with the `updated` handler rather than a plan later, so no released state double-syncs on restore |
| T-04-22 | Tampering | observer constructed with per-model state | high | mitigate | Registration is by class string and the binding is resolved by `get_class($model)` per event; a constructor-captured binding passes for exactly one bound model and silently syncs the wrong object type for the second |
</threat_model>
