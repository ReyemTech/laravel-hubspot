<workspace_placement_decision>
Vitest lives in **`resources/js/`, a workspace of its own — not in `site/`.** This resolves
01-RESEARCH.md Open Question 3, which CONTEXT.md leaves to Claude's discretion.

The reason is not tidiness. If the docs site and the frontend JavaScript share one workspace, the
coverage number that gates a merge is computed across Astro/Starlight content plus the listener.
Documentation content is trivially "covered" in bulk, so a listener with a genuinely untested
origin-validation branch could still clear 95% overall. The floor that exists to protect the single
most security-sensitive file in the package would then be measuring the wrong thing, while
reporting green.

`site/` gets its own workspace in plan 06 and is deliberately excluded from this coverage gate.
</workspace_placement_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> repository | Package installs execute registry-supplied code at install and test time |
| Pull request -> GitHub Actions runner | Untrusted contributor JavaScript runs in the workflow |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-SC | Tampering | npm installs (`vitest`, `@vitest/coverage-v8`, `pnpm`) | high | mitigate | All three returned SUS from the legitimacy gate. Blocking human checkpoint above verifies each registry page and repository link before install; `pnpm-lock.yaml` is committed and CI installs with `--frozen-lockfile` so a later registry substitution cannot silently enter the tree |
| T-03-01 | Tampering | `pnpm install` lifecycle scripts | medium | mitigate | pnpm does not run dependency lifecycle scripts by default. Do not add an `.npmrc` setting that re-enables them for transitive packages |
| T-03-02 | Elevation of Privilege | `.github/workflows/js.yml` | medium | mitigate | `permissions: contents: read`; no secrets consumed. The workflow runs contributor JavaScript, so it must never be given a write token |
| T-03-03 | Information Disclosure | Vitest test execution | low | mitigate | D-12: no network I/O in the suite. The placeholder module has no I/O at all |
| T-03-04 | Tampering | coverage threshold configuration | high | mitigate | The 95% floor guards the Phase 8 origin-validating listener. Task 2 proves the threshold fails a build rather than assuming it; `coverage.include` is scoped to this workspace so the docs site cannot dilute the number |
</threat_model>
