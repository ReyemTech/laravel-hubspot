Write the self-test first and commit it red (D-13).

Create `scripts/ci/check-source-hygiene.sh` implementing D-07: no deferred-work marker reaches
`main`, because a marker is a decision deferred where nobody will find it, and CI turns it into an
issue instead. The two markers are the conventional `TODO` and `FIXME` comment tokens.

Three implementation details decide whether this gate works or becomes a running joke:

First, **the script must not match itself.** It necessarily contains both marker strings in order
to search for them. Exclude its own path explicitly, and exclude comment lines from the files it
scans, so a header comment explaining the gate cannot fail the gate. Build the search literals from
concatenated fragments if the exclusion proves fragile — a self-tripping hygiene check gets
disabled within a week, which is worse than not having one.

Second, **scope it to tracked source.** Scan the PHP, JavaScript, TypeScript and workflow files
under version control. Exclude `vendor/`, `node_modules/`, `site/dist/`, `resources/js/coverage/`
and `.planning/` — the planning directory legitimately discusses deferred work, that being its job.
Prefer `git ls-files` over a filesystem walk so ignored paths are excluded by construction.

Third, **give it a self-test.** `--self-test` writes a temp file carrying each marker, runs the
scan against it, asserts rejection, and cleans up. Wire the self-test into CI alongside the scan
itself, for the same reason plan 04 runs its firing harness on every pull request: an unproven gate
and an absent gate are indistinguishable from the outside.

Then add the mutation floor: `vendor/bin/pest --mutate --min=80` per D-43, using `pest --mutate`
and never Infection — STANDARDS §6 and §12b were corrected on 2026-07-26 and any remaining
Infection reference is stale.

**Answer the empty-`src/` mutation question by running it, not by reasoning about it**, exactly as
plan 01 did for the coverage floor. With no source files there are no mutants. Observe whether Pest
reports 100%, reports 0%, or declines to compute a score, and record the exact output verbatim in
the SUMMARY. The `--min=80` flag stays and the number stays at 80: no gate disabled temporarily is
a cross-phase invariant. Whatever you do must leave a genuine sub-80% score failing in Phase 2.
Cross-check your finding against plan 01's recorded coverage observation and note whether the two
tools behave the same way over an empty source tree.

Create `.github/workflows/quality.yml` with `permissions: contents: read`, on `pull_request`, with
named jobs for: PHPStan, Pint, code shape, source hygiene, the quality-gate firing harness, and
mutation. Give the mutation job a `needs:` on nothing in this workflow but note in the SUMMARY that
it is only meaningful once the tests job is green, since `pest --mutate` runs only the tests
covering each mutation.
