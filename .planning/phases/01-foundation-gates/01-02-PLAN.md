<objective>
Ship the repository governance and security surface, and the commit-message gate that D-25's
merge-commit strategy makes mandatory.

Purpose: `SECURITY.md` is required "from day one" by STANDARDS §10 and D-22 — ADR precedence moved
it out of the core design spec's final phase specifically so it lands before any code. commitlint
is not optional decoration: with merge commits, release-please derives the version bump from the
individual commits on `main`.

Output: `SECURITY.md`, Dependabot config, `CODEOWNERS`, PR and issue templates carrying the
seven-box Definition of Done, a governance check script, and the workflow that runs both it and
commitlint.
</objective>

Add a commitlint job to `.github/workflows/governance.yml` using
`wagoid/commitlint-github-action@v6` with `configFile: commitlint.config.mjs` and `failOnWarnings:
false`. Leave `commitDepth` unset — that is what makes it lint every commit in the pull request
rather than only the head. This is the entire point under D-25: merge commits mean a stray `feat:`
buried in a branch reaches `main` and bumps the minor version, and a head-only or title-only check
would never see it.

The checkout step for this job needs `fetch-depth: 0` so the full commit range is available to
compare against the base branch.

bundles `@commitlint/config-conventional` itself. Plan 03 may or may not introduce a root

answer in the SUMMARY. If the action does turn out to need a root manifest, add the minimal one —
do not weaken the check to `commitDepth: 1` to route around it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public reporter -> maintainer | A security researcher needs a channel that is not a public issue |
| Pull request -> GitHub Actions runner | Untrusted contributor commit messages and files are processed by a workflow |
| Dependency registries -> repository | Dependabot opens PRs that modify the dependency tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | vulnerability reporting path | high | mitigate | `SECURITY.md` publishes a private disclosure address and `ISSUE_TEMPLATE/config.yml` routes security reports away from public issues, so a reporter is not funnelled into disclosing a live vulnerability publicly |
| T-02-02 | Tampering | Dependabot auto-merge of dev-dependency bumps | medium | mitigate | D-31 limits auto-merge to patch and minor dev-dependency bumps and only on green. `composer audit` (plan 07) and the full matrix (plan 01) are the gates that "green" means. Enabling auto-merge is a repository setting and therefore owner action |
| T-02-03 | Elevation of Privilege | `governance.yml` on `pull_request` | medium | mitigate | `permissions: contents: read`, no secrets consumed by any job in this workflow. The commitlint action reads commit metadata only |
| T-02-04 | Repudiation | commit history on `main` | medium | mitigate | commitlint on every commit (D-25, D-26) keeps the history machine-readable, which is what lets release-please derive an honest changelog rather than one with silently dropped commits |
| T-02-SC | Tampering | `wagoid/commitlint-github-action` | medium | accept | Third-party Docker action pinned to major `@v6`. Accepted rather than mitigated by SHA pin because Dependabot's `github-actions` ecosystem (task 1) is configured to surface updates, and the action consumes no repository secret |
</threat_model>
