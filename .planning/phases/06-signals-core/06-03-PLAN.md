<objective>
Bind a visitor to a person, and refuse the two bindings that would write the wrong data.

Purpose: `identify()` is the moment anonymous behaviour becomes attributed behaviour, and it is the
last point where a mistake is cheap. It issues no HTTP, so throwing there costs nothing — while the
alternative surfaces hours later in a worker log detached from its cause, which is the
acknowledged-then-lost shape Phase 5 spent a review round eliminating (D-02).

Output: `Exceptions\SignalException` as the fifth member of the hierarchy, a complete
`Signals\IdentityResolver` implementing D-02 and D-09, and the identify surface on the facade.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consuming app → `Hubspot::identify()` | An application-supplied visitor id and an application-owned model cross into package-owned identity state. The app has already authorised the call; the package decides whether the binding is coherent. |
| `hubspot_signals` subject columns → later flush | Whatever `identify()` writes here decides which HubSpot record receives the roll-up. A wrong binding writes a real person's behaviour onto another real person's record. |
| package → operator logs / exception messages | `SignalException` messages cross into a log stream whose audience is not the data subject. |
