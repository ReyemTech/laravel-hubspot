<objective>
Ship the declarative signal map: a closed four-verb vocabulary, an invokable class-string escape
hatch that survives `config:cache`, and boot-time validation that fails fast.

Purpose: a bad signal map silently drops the buffered attribution the whole feature exists to
protect. That is a worse failure than a bad webhook handler map, which costs one claim — which is
exactly why D-07 validates at boot where `HandlerMap` validates at job time. Fail-fast is worth more
here than there.

Output: `Signals\MergeRule`, `Signals\SignalMap`, `Signals\Contracts\SignalCalculator`,
`ServiceProvider::bootSignalMap()`, four new `ConfigurationException` factories, and the two spec
amendments D-08 requires.
</objective>

`validate()` walks `config('hubspot.signals.map', [])` once in declared array order and throws on
the first bad entry — the shape `HandlerMap::validate()` proves, and the reason Test 7 exists. Per
entry it checks: the `object` key is present and normalises through

map and `'Contacts'` in `hubspot.models` would otherwise false-positive an exception on two
declarations that name the same object. D-03 is boot-checkable precisely because "is this object
type claimed by some bound model" needs no runtime subject.

A signal name appearing twice in the config array is resolved by PHP's own array-key semantics
before this class is constructed, so `validate()` sees one entry and there is no duplicate to
detect. Record that in the docblock rather than writing a detection branch that can never fire.
