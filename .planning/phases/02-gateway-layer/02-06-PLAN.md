## The specified surface

The design spec's example reads: `Hubspot::fake()`, `Hubspot::fake(['deals' => Hubspot::response(...)])`,
`Hubspot::assertSynced($deal)`, `Hubspot::assertAssociated($deal, $contact, label: 'buyer')`,
`Hubspot::assertNothingSynced()`, `Hubspot::assertRequestCount(1)`.

Two of those take Eloquent models, and there is no model binding in this package until Phase 4
(SYNC-01). Resolve it forward-compatibly rather than by deferring:

- `assertSynced` takes the object type as a string now, with an optional property expectation.
  Phase 4 widens the first parameter to accept a bound model as well. Widening a parameter type is
  safe for callers and for this `final` class.
- `assertAssociated` takes an `AssociationPair` and a named label. It does **not** take two bare
  object references, because no API in this package accepts two objects without an order — that
  rule binds the test surface exactly as it binds the write surface. Phase 4 can add a factory that
  builds a pair from two models so the call site reads close to the spec's example while keeping
  the direction explicit.

State both decisions in the summary so they read as deliberate rather than as drift from the spec.

## `assertWebhookHandled` — decided, not dropped

GW-04's acceptance criteria and design spec §10 both list `assertWebhookHandled`. It is **not**
shipped in Phase 2, deliberately:

- CONTEXT.md's phase boundary excludes webhooks explicitly; they are Phase 5.
- There is no webhook path to assert against, so any implementation would be a no-op or an
  always-failing stub. A no-op assertion is worse than an absent one — it passes and proves
  nothing, which is the precise failure mode this package's mutation floor exists to catch. It
  would also be unreachable code dragging on the coverage and MSI floors.
- Adding a method to a `final` class later is additive and semver-safe (D-17), so deferring costs
  nothing. `roave/backward-compatibility-check` does not flag an addition.

Record it in this phase's deferred-items file so Phase 5 picks it up as a known obligation rather
than rediscovering it.

## Working method

TDD with the RED commit first (D-13), one branch off a freshly pulled `main` and one PR (D-24),
Conventional Commits (D-26), `declare(strict_types=1)` (D-34), `final` by default (decision #5),
PHPStan level max with no baseline (D-04), no `TODO`/`FIXME` (D-07), no real network I/O (D-12).
File-level `mutates(ClassName::class)`, not `covers()`.

Determinism is a correctness property here (D-10): time is frozen with `Carbon::setTestNow()` and
never slept on, randomness is seeded, ordering is never assumed. Faker stays out of the default
fake entirely — it is `require-dev` only and every future call site must be guarded by a class
existence check (D-03).
