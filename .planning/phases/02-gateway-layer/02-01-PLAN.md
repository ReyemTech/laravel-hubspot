## Verified SDK facts this plan depends on (read before writing code)

Every signature below was read from the installed `hubspot/api-client` 14.1.0 in
`vendor/hubspot/api-client` and confirmed by an executed reproduction — do not re-derive them,
and do not assume anything not listed here.

- `HubSpot\Factory::createWithAccessToken(string $accessToken, ?GuzzleHttp\ClientInterface $client = null)`
  returns `HubSpot\Discovery\Discovery`. The injected client is stored once and threaded through
  every `->crm()->objects()->basicApi()` resolution by `DiscoveryBase::__call()`.
- `crm()->objects()->basicApi()->create($object_type, $simple_public_object_input_for_create)`.
- The create input model is `HubSpot\Client\Crm\Objects\Model\SimplePublicObjectInputForCreate`,
  constructed from an array with a `properties` key.
- The declared return of `create()` is the union `SimplePublicObject|Error`. PHPStan level max
  enforces it. **Narrow with `instanceof`, never with a suppression** — this was reproduced
  both ways and `instanceof` clears it with zero suppression comments.
- The SDK has no shared `ApiException` base class. It is codegen'd per namespace; the one this
  plan can receive is `HubSpot\Client\Crm\Objects\ApiException`, which exposes `getCode()`,
  `getResponseBody()`, `getResponseHeaders()` and `getResponseObject()`.
- `getResponseObject()` returns a typed `Model\Error` for a real HTTP error response, and
  **null** for a connection-level failure (where `getCode()` is 0 and `getResponseBody()` is
  null). Null-check it.

## Dependency policy note — read before touching composer.json

`guzzlehttp/guzzle` and `guzzlehttp/psr7` are hard `require` entries of `hubspot/api-client`
itself, and the SDK's own injection seam is typed on `GuzzleHttp\ClientInterface`. Wrapping the
SDK without naming a Guzzle type is therefore impossible. **Do not add Guzzle to
`composer.json`** — production requires stay at exactly seven (D-02), and
`tests/Ci/ComposerManifestTest.php` already fails the build if an eighth appears. Record the
reasoning in the class header of `HubspotClientFactory` so a later reader does not "fix" it.

## Test-suite conventions established in Phase 1

- Use file-level `mutates(ClassName::class)` — `covers()` does not attach to PHPUnit-style test
  methods in this repository (confirmed in `01-05-SUMMARY.md`; working example at
  `tests/Feature/ServiceProviderTest.php:28`).
- `tests/Pest.php` applies `TestCase` to `Feature` and `Unit`. `phpunit.xml.dist` currently
  declares only `Feature`, `Ci` and `Arch` testsuites and `tests/Ci/PhpunitTestsuitesTest.php`
  asserts exactly those three. **Put every test in this plan under `tests/Feature/` or
  `tests/Arch/`.** Creating `tests/Unit/` here would either not run or break that lock; plan
  02-04 registers the `Unit` suite in the same commit as the first unit test.
- `tests/TestCase::getPackageProviders()` currently returns an empty array. This plan changes it
  to register `ServiceProvider::class`, because nearly every Gateway test needs the container
  bound. Leave `tests/Feature/ServiceProviderTest.php`'s local override in place — the
  duplication is harmless.
- Mutation testing (MSI ≥ 80, D-43) is unforgiving of a wrapper that only forwards arguments.
  Assert on the **recorded PSR-7 request** — method, URI path, and decoded JSON body — not just
  on the returned object, or every mutation to a forwarded argument survives.

Build these pieces, and only these:

`src/Exceptions/HubspotException.php` — an interface, no methods, the package-owned root every
member of the hierarchy implements (D-18). Not a class: consumers must be able to catch the root
across members that legitimately extend different SPL parents.

`src/Exceptions/ApiException.php` — `final`, extends `RuntimeException`, implements
`HubspotException`. Readonly accessors for the HTTP status, the raw response body and HubSpot's
correlation id, all nullable where the SDK can legitimately supply nothing. Its message names the
fix, not just the fault (D-18): include the status and the correlation id so a reader can quote
them to HubSpot support. It must never carry, echo or expose the access token or any request
header — see the threat register.

`src/Gateway/HubspotClientFactory.php` — `final`. The single place in the package that names
`HubSpot\Factory`. Two named constructors: one that builds the production transport from the
package config, and one, `forTransport()`, taking a `GuzzleHttp\ClientInterface` so the fake can
inject a mock-backed client. One method returning the SDK `Discovery`. For this task the
production path may take the token straight from config with no validation — plan 02-02 adds the
missing-token `ConfigurationException`, the timeout and the retry middleware. Put the Guzzle
dependency-policy note from the context section in the class header.

`src/Gateway/ExceptionTranslator.php` — `final`. One method that takes a `Throwable` and returns
the package `ApiException`. For this task it recognises `HubSpot\Client\Crm\Objects\ApiException`
only; plan 02-02 adds the associations namespace. Extract status from `getCode()`, body from
`getResponseBody()`, and the correlation id from `getResponseObject()` guarded by a null check.
Structure the recognised set as a single explicit list so adding a namespace later is a one-line
change with an obvious place for its test.

`src/Gateway/HubspotObject.php` — `final`, readonly, package-owned: object type, id, and a
properties array. This is what leaves the Gateway. **No SDK type may appear in any Gateway return
type or public parameter type**, or Phase 3 and 4 will violate R1 the moment they consume it.

`src/Gateway/Contracts/ObjectGatewayContract.php` — the interface the container binds and the
documented extension point (decision #5). For this task it declares `create()` only.

`src/Gateway/ObjectGateway.php` — `final`, implements the contract. Takes the client factory by
constructor injection. `create()` accepts the object type as a plain string and a properties
array, builds `SimplePublicObjectInputForCreate`, calls the generic
`crm()->objects()->basicApi()->create()`, narrows the `SimplePublicObject|Error` union with
`instanceof`, and maps to `HubspotObject`. Wrap the SDK call in a try/catch that routes through
the translator. No object-type-specific branch anywhere.

`src/HubspotManager.php` — `final`, namespace `ReyemTech\Hubspot`. The object the facade resolves.
For this task: `objects()` returning the bound `ObjectGatewayContract`, plus `fake()`,
`response()` and `assertRequestCount()`. Every assertion method fails with a clear message naming
`fake()` when no fake is installed.

`src/Testing/HubspotFake.php` — `final`. Owns the `MockHandler`, the `HandlerStack` with
`Middleware::history()` pushed onto it, the object-type-keyed canned response map, the id counter,
and read accessors for the recorded requests. It builds a `GuzzleHttp\Client` and installs it by
putting `HubspotClientFactory::forTransport($client)` into the container as the
`HubspotClientFactory` instance, then forgetting the previously resolved gateway bindings so the
next resolution picks up the mock transport. It must not name any `HubSpot\*` class — Guzzle types
are fine here, SDK types are not (R1).

`src/Facades/Hubspot.php` — `final`, extends `Illuminate\Support\Facades\Facade`, accessor

`src/ServiceProvider.php` — extend the existing file, do not rewrite it. Bind

this file** — it lives in `ReyemTech\Hubspot`, not `ReyemTech\Hubspot\Gateway`, so a single

## Trust Boundaries
