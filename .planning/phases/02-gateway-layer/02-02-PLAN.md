<objective>
Complete the typed exception hierarchy to all four members rooted at `HubspotException`, and turn
the production Guzzle transport from a bare client into a deliberate one — explicit timeouts,
the SDK's own retry middleware for 429 and 5xx, and a `ConfigurationException` when the token is
missing.

Purpose: success criterion 3 is absolute — a raw SDK exception must never reach userland, and a
consumer must be able to catch our four types. Plan 02-01 shipped the root and `ApiException` on
one path; this plan finishes the hierarchy and closes the "no timeout, no retries" default that
the SDK silently inherits, which is a real outage in a queued sync job.

Output: `ConfigurationException`, `ObjectTypeException`, `AssociationTypeException`, a translator
covering every namespace the Gateway calls, a production transport with a documented timeout and
retry policy, and the secret-key reconciliation the Phase 1 arch test explicitly asked for.
</objective>

## Verified SDK facts this plan depends on

- `HubSpot\RetryMiddlewareFactory` ships in the SDK at `vendor/hubspot/api-client/lib/RetryMiddlewareFactory.php`
  and exposes `createRateLimitMiddleware()` (HTTP 429) and `createInternalErrorsMiddleware()`
  (5xx). It is **not** wired into `Factory::create()` or any Discovery class automatically — it is
  opt-in plumbing the consumer attaches to their own `HandlerStack`.
- The SDK sets no `timeout` and no `connect_timeout` anywhere. `Factory::createWithAccessToken()`
  constructs a bare Guzzle client when none is passed.
- The per-namespace `ApiException` classes this phase's Gateway can receive are
  `HubSpot\Client\Crm\Objects\ApiException` and `HubSpot\Client\Crm\Associations\V4\ApiException`.
  There are 60 such classes in the SDK and **no shared base class** — do not write a catch that
  assumes one.

## Scope note on the third namespace

Research suggested also covering `HubSpot\Client\Crm\Associations\V4\Schema\ApiException`. Do not
add it in this phase: nothing in Phase 2 calls the Schema definitions API — that is Phase 3's
registry reconciliation — so the branch would be unreachable code dragging on the coverage and
mutation floors. Task 1 instead adds a test that fails the build the moment the Gateway starts
calling a namespace the translator does not recognise, which is a stronger guarantee than a
speculative entry.

come from the same code generator, so one translation routine handles both.
